# A guide to spicule

This guide walks through spicule one step at a time. The exact rules are in the
specs: [`hdl-spec.md`](hdl-spec.md), [`sim-spec.md`](sim-spec.md) and
[`ir-spec.md`](ir-spec.md).

## 1. A first cell

Every design starts with its primitives: the devices it uses. A PDK device or an
IP block is defined outside the netlist, but still gets instantiated in it, so
spicule needs to know its interface. You declare that interface as an **external
cell**.

```python
import spicule.hdl as h
from spicule.dialects import cdl, spectre

nch = h.External("nch", element=h.MOS, ports=[h.Port(name="d"), h.Port(name="g"), h.Port(name="s"), h.Port(name="b")])
pch = h.External("pch", element=h.MOS, ports=[h.Port(name="d"), h.Port(name="g"), h.Port(name="s"), h.Port(name="b")])
```

A cell of your own is a class deriving from `h.Subckt`. The class name is the
cell name, and each attribute name is the name of a port or instance. An
instance takes two calls: parameters first, then connections.

```python
class inv(h.Subckt):
    a = h.Port()
    y = h.Port()
    vdd = h.Port()
    vss = h.Port()
    mp = pch()(d=y, g=a, s=vdd, b=vdd)
    mn = nch()(d=y, g=a, s=vss, b=vss)
```

`h.elaborate` checks the design and gives a netlist, which each writer spells in
its own way. External cells aren't written, since they are defined elsewhere.

```python
netlist = h.elaborate(inv)
print(spectre.write(netlist))
print(cdl.write(netlist))
```

```text
// Generated by spicule
simulator lang=spectre

subckt inv (a y vdd vss)
    mp (y a vdd vdd) pch
    mn (y a vss vss) nch
ends inv

* Generated by spicule

.SUBCKT inv a y vdd vss
Mmp y a vdd vdd pch
Mmn y a vss vss nch
.ENDS inv

.END
```

## 2. Hierarchy

An instance of your own cell looks the same as an instance of a device. A net
that isn't a port is an `h.Signal`.

```python
class buf(h.Subckt):
    a = h.Port()
    y = h.Port()
    vdd = h.Port()
    vss = h.Port()
    mid = h.Signal()
    i0 = inv()(a=a, y=mid, vdd=vdd, vss=vss)
    i1 = inv()(a=mid, y=y, vdd=vdd, vss=vss)


print(spectre.write(h.elaborate(buf)))
```

```text
// Generated by spicule
simulator lang=spectre

subckt inv (a y vdd vss)
    mp (y a vdd vdd) pch
    mn (y a vss vss) nch
ends inv

subckt buf (a y vdd vss)
    i0 (a mid vdd vss) inv
    i1 (mid y vdd vss) inv
ends buf
```

## 3. Parameters

A subckt declares *netlist parameters* with `h.Param`, each with a default. The
simulator evaluates them, so Python arithmetic on a parameter doesn't calculate:
it builds an expression that is written into the netlist. Functions are in
`h.fn`.

An instance of an external cell can set any parameter, because the PDK owns
those. An instance of a subckt can only set what the subckt declares.

```python
class inv(h.Subckt):
    a = h.Port()
    y = h.Port()
    vdd = h.Port()
    vss = h.Port()
    nfin = h.Param(default=2)
    l = h.Param(default=16e-9)  # noqa: E741
    mp = pch(nfin=2 * nfin, l=h.fn.max(l, 20e-9))(d=y, g=a, s=vdd, b=vdd)
    mn = nch(nfin=nfin, l=l)(d=y, g=a, s=vss, b=vss)


class buf(h.Subckt):
    a = h.Port()
    y = h.Port()
    vdd = h.Port()
    vss = h.Port()
    mid = h.Signal()
    i0 = inv()(a=a, y=mid, vdd=vdd, vss=vss)
    i1 = inv(nfin=4)(a=mid, y=y, vdd=vdd, vss=vss)


print(spectre.write(h.elaborate(buf)))
```

```text
// Generated by spicule
simulator lang=spectre

subckt inv (a y vdd vss)
    parameters nfin=2 l=16e-9
    mp (y a vdd vdd) pch nfin=2*nfin l=max(l, 20e-9)
    mn (y a vss vss) nch nfin=nfin l=l
ends inv

subckt buf (a y vdd vss)
    i0 (a mid vdd vss) inv
    i1 (mid y vdd vss) inv nfin=4
ends buf
```

Numbers are exact. A float goes through its shortest text, so `16e-9` stays
exactly that, and writers print engineering notation. There are no scale
factors such as `16n`, because tools disagree on what they mean.

## 4. Buses

A bus has real bit names, as in Cadence: `h.Port(width=4)` is `d<3:0>`, and an
index names those bits. So `d[3:2]` is two bits, both ends included. **This is
not a Python slice.** Reversing is writing it the other way around: `d[0:3]`.

`h.Concat` joins pieces in the order written, and `h.NoConn` leaves bits open on
purpose. Writers give each open bit its own net, so open pins never short by
accident.

```python
latch = h.External("latch4", h.SUBCKT, [h.Port(name="d", width=4), h.Port(name="q", width=4), h.Port(name="clk")])


class bank(h.Subckt):
    d = h.Port(width=4)
    q = h.Port(width=4)
    en = h.Port()
    clk = h.Port()
    u0 = latch()(d=h.Concat(d[3:2], en, h.NoConn(1)), q=q[0:3], clk=clk)


print(spectre.write(h.elaborate(bank)))
print(cdl.write(h.elaborate(bank)))
```

```text
// Generated by spicule
simulator lang=spectre

subckt bank (d\<3\> d\<2\> d\<1\> d\<0\> q\<3\> q\<2\> q\<1\> q\<0\> en clk)
    u0 (d\<3\> d\<2\> en nc_u0_0 q\<0\> q\<1\> q\<2\> q\<3\> clk) latch4
ends bank

* Generated by spicule

.SUBCKT bank d<3> d<2> d<1> d<0> q<3> q<2> q<1> q<0> en clk
Xu0 d<3> d<2> en nc_u0_0 q<0> q<1> q<2> q<3> clk latch4
.ENDS bank

.END
```

SPICE has no buses, so every bit becomes a net of its own, spelled per dialect.

## 5. External cells

`element` says what the name refers to, because CDL calls each kind with its own
letter. Spectre doesn't need that letter, but one declaration serves both.

| `element` | The name is | CDL line |
| --- | --- | --- |
| `h.MOS` | a transistor model | `M...` |
| `h.RESISTOR`, `h.CAPACITOR`, `h.INDUCTOR` | a passive model | `R...`, `C...`, `L...` |
| `h.DIODE`, `h.BIPOLAR` | a diode or bipolar model | `D...`, `Q...` |
| `h.SUBCKT` | a subcircuit in another file | `X...` |
| `h.BUILTIN` | an element of the simulator itself | (step 9) |

A `str` value on an external cell is text. Anything else is a number.

```python
rpoly = h.External("rpoly", h.RESISTOR, [h.Port(name="p"), h.Port(name="n")])


class load(h.Subckt):
    a = h.Port()
    b = h.Port()
    r0 = rpoly(l=1e-6, flavor="hv")(p=a, n=b)


print(cdl.write(h.elaborate(load)))
```

```text
* Generated by spicule

.SUBCKT load a b
Rr0 a b rpoly l=1e-6 flavor="hv"
.ENDS load

.END
```

## 6. Shortcuts

Everything so far is the explicit form. It stays valid, and each shortcut stands
for it without changing the netlist.

| Explicit | Shortcut |
| --- | --- |
| `h.External("n", element=h.MOS, ports=[h.Port(name="d"), ...])` | `h.External("n", h.MOS, "d g s b")`, a bus as `d[3:0]` |
| `a = h.Port()`, `y = h.Port()` | `a, y = h.Ports(2)`, also `h.Signals` |
| `h.Param(default=2)` | `h.Param(2)` |
| `inv()(a=a, y=y, vdd=vdd, vss=vss)` | `inv()(a, y, vdd, vss)`, in port order |
| `h.Concat(d[3:2], en)` | `(d[3:2], en)` |
| one call per device | a template: `.preset()` connects ports, `.params()` overrides |

Connecting by position can't catch two swapped ports of equal width, so it suits
small cells. A template needs a `_` name, which keeps it out of the cell, as for
any helper.

```python
nch = h.External("nch", h.MOS, "d g s b")
pch = h.External("pch", h.MOS, "d g s b")


class inv(h.Subckt):
    a, y, vdd, vss = h.Ports(4)
    nfin = h.Param(2)
    mp = pch(nfin=2 * nfin)(y, a, vdd, vdd)
    mn = nch(nfin=nfin)(y, a, vss, vss)


class nand2(h.Subckt):
    a, b, y, vdd, vss = h.Ports(5)
    mid = h.Signal()
    _p = pch().preset(d=y, s=vdd, b=vdd)
    _n = nch(nfin=4).preset(b=vss)
    mpa = _p(g=a)
    mpb = _p(g=b)
    mna = _n(d=y, g=a, s=mid)
    mnb = _n.params(nfin=6)(d=mid, g=b, s=vss)


print(spectre.write(h.elaborate(nand2)))
```

```text
// Generated by spicule
simulator lang=spectre

subckt nand2 (a b y vdd vss)
    mpa (y a vdd vdd) pch
    mpb (y b vdd vdd) pch
    mna (y a mid vss) nch nfin=4
    mnb (mid b vss vss) nch nfin=6
ends nand2
```

## 7. Generators

A class is one cell. A decorated function is a family of cells: its arguments are
*build parameters*, Python values that decide structure. It runs once per
distinct value, and the format on the decorator names each cell.

A class body can't make names in a loop, so a loop sets them on the class.

```python
@h.generator("invbank_n{n}")
def invbank(*, n: int) -> type[h.Subckt]:
    class bank(h.Subckt):
        d, q = h.Ports(2, width=n)
        vdd, vss = h.Ports(2)
        nfin = h.Param(4)

    for bit in range(n):
        setattr(bank, f"x{bit}", inv(nfin=bank.nfin)(bank.d[bit], bank.q[bit], bank.vdd, bank.vss))
    return bank


class top(h.Subckt):
    din, dout = h.Ports(2, width=2)
    vdd, vss = h.Ports(2)
    mid = h.Signal(width=2)
    b0 = invbank(n=2)(nfin=6)(din, mid, vdd, vss)
    b1 = invbank(n=2)()(mid, dout, vdd, vss)


print(spectre.write(h.elaborate(top)))
```

```text
// Generated by spicule
simulator lang=spectre

subckt inv (a y vdd vss)
    parameters nfin=2
    mp (y a vdd vdd) pch nfin=2*nfin
    mn (y a vss vss) nch nfin=nfin
ends inv

subckt invbank_n2 (d\<1\> d\<0\> q\<1\> q\<0\> vdd vss)
    parameters nfin=4
    x0 (d\<0\> q\<0\> vdd vss) inv nfin=nfin
    x1 (d\<1\> q\<1\> vdd vss) inv nfin=nfin
ends invbank_n2

subckt top (din\<1\> din\<0\> dout\<1\> dout\<0\> vdd vss)
    b0 (din\<1\> din\<0\> mid\<1\> mid\<0\> vdd vss) invbank_n2 nfin=6
    b1 (mid\<1\> mid\<0\> dout\<1\> dout\<0\> vdd vss) invbank_n2
ends top
```

That first instance has three calls, one per layer: build parameters, netlist
parameters, connections. Both instances share one cell, because equal values give
the same cell.

A value that changes the structure or is text is a build parameter. A number the
simulator may vary is a netlist parameter.

## 8. Mistakes

Mistakes are an `h.HdlError` as soon as they can be known, naming the Python
lines involved.

```python
for mistake in (
    "inv(nfins=4)",
    "inv()(a=1)",
    'inv(nfin="2u")',
    "invbank(n=[2])",
):
    try:
        eval(mistake)
    except h.HdlError as error:
        print(f"{mistake}: {str(error).splitlines()[0]}")
```

```text
inv(nfins=4): inv has no parameter 'nfins' (parameters: nfin)
inv()(a=1): port 'a' of inv can't be connected to 1
inv(nfin="2u"): parameter nfin of inv is a number, got the text '2u'. Subckt parameters are numbers; a text choice is a build parameter of a generator
invbank(n=[2]): generator invbank: argument n=[2] can't be a build parameter, because it isn't hashable; use a tuple instead of a list, for example
```

`h.elaborate(top, lint=True)` also warns about floating nets, which don't make a
netlist invalid. Writers can trace a line back to its Python source with
`origins=True`, which adds comments such as `// origin: cells/inv.py:8`.

## 9. A simulation

A testbench is an ordinary subckt, using the simulator's own elements from
`spicule.hdl.builtins`. In the HDL, ground is just another net.

```python
from spicule.hdl.builtins import spectre as sp


class tb(h.Subckt):
    supply = h.Param(0.8)
    vdd, a, y, gnd = h.Signals(4)
    dut = inv(nfin=4)(a, y, vdd, gnd)
    vs = sp.vsource(type="dc", dc=supply)(vdd, gnd)
    va = sp.vsource(type="pulse", val0=0, val1=supply, period=1e-9)(a, gnd)
    cl = sp.capacitor(c=1e-15)(y, gnd)
```

Which models to load, what to run and which net is ground aren't part of the
circuit, since the same circuit also goes to LVS. They are in a `sim.Simulation`.
Spectre owns the names of analyses and of their parameters, so any can be given.
`params` sets parameters that the top cell declares, and a sweep or a Monte Carlo
run holds the analyses it repeats in `children`.

```python
from spicule import sim

run = sim.Simulation(
    h.elaborate(tb),
    top="tb",
    ground="gnd",
    params={"supply": 0.7},
    includes=[sim.Include("models.scs", section="tt")],
    options=sim.Options("opts", temp=27),
    saves=["y", "dut.mp:d"],
    analyses=[
        sim.Analysis("op", "dc"),
        sim.Analysis("tr", "tran", stop=2e-9),
        sim.Analysis("sw", "sweep", param="supply", values=[0.6, 0.8], children=[sim.Analysis("op", "dc")]),
    ],
)
print(spectre.write(run))
```

```text
// Generated by spicule
simulator lang=spectre

parameters supply=700e-3
include "models.scs" section=tt

subckt inv (a y vdd vss)
    parameters nfin=2
    mp (y a vdd vdd) pch nfin=2*nfin
    mn (y a vss vss) nch nfin=nfin
ends inv

// top: tb
dut (a y vdd 0) inv nfin=4
vs (vdd 0) vsource type=dc dc=supply
va (a 0) vsource type=pulse val0=0 val1=supply period=1e-9
cl (y 0) capacitor c=1e-15

opts options temp=27
save y dut.mp:d

op dc
tr tran stop=2e-9
sw sweep param=supply values=[600e-3 800e-3] {
    op dc
}
```

`spectre.write` takes the netlist or the simulation. A netlist is a library of
subcircuits, and a simulation is a deck to run. For anything the structure
doesn't cover, `raw=[...]` and `sim.Raw` hold Spectre text as it is.

## 10. Files and the IR

`jsonio` writes a netlist or a simulation as a JSON file, for looking at it,
comparing runs with `diff`, or keeping a design without its Python.

```python
from spicule.dialects import jsonio

text = jsonio.write(run)
print(text.splitlines()[1])
print(jsonio.read(text) == run)
```

```text
"format": "spicule.sim/1",
True
```

What `h.elaborate` returns is the IR: plain frozen dataclasses, one validator, and
nothing of the HDL left. A tool can read it directly.

```python
import spicule.ir as ir

netlist = h.elaborate(inv)
for cell in netlist.cells:
    print(type(cell).__name__, cell.name, [port.name for port in cell.ports])
mp = netlist.cells[-1].instances[0]
print(mp.name, mp.cell, ir.format_expression(mp.params[0].value))
```

```text
External pch ['d', 'g', 's', 'b']
External nch ['d', 'g', 's', 'b']
Subckt inv ['a', 'y', 'vdd', 'vss']
mp pch 2*nfin
```
