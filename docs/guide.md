# A guide to spicule

This guide walks through spicule one step at a time. The exact rules are in the
specs: [`hdl-spec.md`](hdl-spec.md), [`sim-spec.md`](sim-spec.md) and
[`ir-spec.md`](ir-spec.md).

## 1. A first cell

Every design builds on **primitives**, things that already exist, such as a PDK
transistor or an IP block. You include these in your netlist and instantiate
them, but they aren't defined there. In spicule, a primitive is an **external
cell**. All spicule needs is its interface: its name, how a netlist calls it and
its ports in pin order.

```python
import spicule.hdl as h
from spicule.dialects import cdl, spectre

nch = h.External("nch", element=h.MOS, ports=[h.Port(name="d"), h.Port(name="g"), h.Port(name="s"), h.Port(name="b")])
pch = h.External("pch", element=h.MOS, ports=[h.Port(name="d"), h.Port(name="g"), h.Port(name="s"), h.Port(name="b")])
```

In contrast, a **subcircuit** is a type of cell you define yourself. It is a
class deriving from `h.Subckt`. The class name is the subcircuit name, and each
attribute is a port or an instance, named after the attribute.

Instantiating a cell takes two calls: first parameters, then connections.

```python
class inv(h.Subckt):
    a = h.Port()
    y = h.Port()
    vdd = h.Port()
    vss = h.Port()
    mp = pch(nfin=4)(d=y, g=a, s=vdd, b=vdd)
    mn = nch(nfin=2)(d=y, g=a, s=vss, b=vss)
```

`h.elaborate` checks the design for mistakes and returns a **netlist**, an
intermediate representation (IR) of your circuit. A **writer** then turns that
netlist into text in its own dialect. External cells aren't written, because
their definitions come from the files you include.

```python
netlist = h.elaborate(inv)
print("----- SPECTRE NETLIST -----")
print(spectre.write(netlist))
print("----- CDL NETLIST -----")
print(cdl.write(netlist))
```

```text
----- SPECTRE NETLIST -----
// Generated by spicule
simulator lang=spectre

subckt inv (a y vdd vss)
    mp (y a vdd vdd) pch nfin=4
    mn (y a vss vss) nch nfin=2
ends inv

----- CDL NETLIST -----
* Generated by spicule

.SUBCKT inv a y vdd vss
Mmp y a vdd vdd pch nfin=4
Mmn y a vss vss nch nfin=2
.ENDS inv

.END
```

## 2. Hierarchy

A real design is built out of smaller cells. A buffer, for example, is two
inverters in a row. An instance of your own subcircuit looks the same as an
instance of a primitive, so hierarchy needs nothing new.

The two inverters share a net that isn't a port of the buffer. Such an internal
net is a **signal**, declared with `h.Signal`.

```python
class buf(h.Subckt):
    a = h.Port()
    y = h.Port()
    vdd = h.Port()
    vss = h.Port()
    mid = h.Signal()
    i0 = inv()(a=a, y=mid, vdd=vdd, vss=vss)
    i1 = inv()(a=mid, y=y, vdd=vdd, vss=vss)


print(spectre.write(h.elaborate(buf)))
```

```text
// Generated by spicule
simulator lang=spectre

subckt inv (a y vdd vss)
    mp (y a vdd vdd) pch nfin=4
    mn (y a vss vss) nch nfin=2
ends inv

subckt buf (a y vdd vss)
    i0 (a mid vdd vss) inv
    i1 (mid y vdd vss) inv
ends buf
```

## 3. Parameters

Most cells come in more than one size, and you don't want a new cell for each. A
**netlist parameter** solves this: the subcircuit declares it with `h.Param`,
with a default, and each instance can set its own value.

The simulator evaluates these parameters, not Python. So arithmetic on a
parameter doesn't calculate: it builds an expression that is written into the
netlist. Functions are in `h.fn`.

An instance of an external cell can set any parameter, because the PDK owns
those. An instance of a subcircuit can only set what the subcircuit declares.

```python
class inv(h.Subckt):
    a = h.Port()
    y = h.Port()
    vdd = h.Port()
    vss = h.Port()
    nfin = h.Param(default=2)
    l = h.Param(default=16e-9)
    mp = pch(nfin=2 * nfin, l=h.fn.max(l, 20e-9))(d=y, g=a, s=vdd, b=vdd)
    mn = nch(nfin=nfin, l=l)(d=y, g=a, s=vss, b=vss)


class buf(h.Subckt):
    a = h.Port()
    y = h.Port()
    vdd = h.Port()
    vss = h.Port()
    mid = h.Signal()
    i0 = inv()(a=a, y=mid, vdd=vdd, vss=vss)
    i1 = inv(nfin=4)(a=mid, y=y, vdd=vdd, vss=vss)


print(spectre.write(h.elaborate(buf)))
```

```text
// Generated by spicule
simulator lang=spectre

subckt inv (a y vdd vss)
    parameters nfin=2 l=16e-9
    mp (y a vdd vdd) pch nfin=2*nfin l=max(l, 20e-9)
    mn (y a vss vss) nch nfin=nfin l=l
ends inv

subckt buf (a y vdd vss)
    i0 (a mid vdd vss) inv
    i1 (mid y vdd vss) inv nfin=4
ends buf
```

Numbers are exact. A float goes through its shortest text, so `16e-9` stays
exactly that, and writers print it in engineering notation. Using textual scale
factors such as `16n` is not allowed because tools disagree on what they mean.

## 4. What a subcircuit holds

You have now seen everything a subcircuit can hold. **Every named attribute of
the class must be a port, a signal, a parameter or an instance.** Anything else
is an error, because it would silently not end up in the written netlist.

To keep a helper in the class anyway, start its name with an underscore, and
spicule leaves it out of the written netlist. A helper is ordinary Python.
Below, `_nfin_out` is an expression over a parameter, and `_power` has nothing
to do with parameters: it holds the supply connections that both inverters
share.

```python
class buf_helper(h.Subckt):
    a = h.Port()
    y = h.Port()
    vdd = h.Port()
    vss = h.Port()
    mid = h.Signal()
    nfin = h.Param(default=2)
    _nfin_out = 2 * nfin  # Without the underscore, this is an error.
    _power = dict(vdd=vdd, vss=vss)
    i0 = inv(nfin=nfin)(a=a, y=mid, **_power)
    i1 = inv(nfin=_nfin_out)(a=mid, y=y, **_power)


print(spectre.write(h.elaborate(buf_helper)))
```

```text
// Generated by spicule
simulator lang=spectre

subckt inv (a y vdd vss)
    parameters nfin=2 l=16e-9
    mp (y a vdd vdd) pch nfin=2*nfin l=max(l, 20e-9)
    mn (y a vss vss) nch nfin=nfin l=l
ends inv

subckt buf_helper (a y vdd vss)
    parameters nfin=2
    i0 (a mid vdd vss) inv nfin=nfin
    i1 (mid y vdd vss) inv nfin=2*nfin
ends buf_helper
```

## 5. Buses

Some nets belong together, such as the bits of a data word. A **bus** groups
them under one name, declared with a width: `h.Port(width=4)` is `d<3:0>`.

Bits keep their real names, and an index uses those names. So `d[3:2]` is two
bits, both ends included. **This is not a Python slice.** To reverse the bits,
write the range the other way around: `d[0:3]`.

A connection doesn't have to be one bus. `h.Concat` joins pieces in the order
written, and `h.NoConn` leaves bits open on purpose. Writers give each open bit
its own net, so open pins never short by accident.

```python
latch = h.External("latch4", h.SUBCKT, [h.Port(name="d", width=4), h.Port(name="q", width=4), h.Port(name="clk")])


class bank(h.Subckt):
    d = h.Port(width=4)
    q = h.Port(width=4)
    en = h.Port()
    clk = h.Port()
    u0 = latch()(d=h.Concat(d[3:2], en, h.NoConn(1)), q=q[0:3], clk=clk)


print(spectre.write(h.elaborate(bank)))
print(cdl.write(h.elaborate(bank)))
```

```text
// Generated by spicule
simulator lang=spectre

subckt bank (d\<3\> d\<2\> d\<1\> d\<0\> q\<3\> q\<2\> q\<1\> q\<0\> en clk)
    u0 (d\<3\> d\<2\> en nc_u0_0 q\<0\> q\<1\> q\<2\> q\<3\> clk) latch4
ends bank

* Generated by spicule

.SUBCKT bank d<3> d<2> d<1> d<0> q<3> q<2> q<1> q<0> en clk
Xu0 d<3> d<2> en nc_u0_0 q<0> q<1> q<2> q<3> clk latch4
.ENDS bank

.END
```

SPICE has no buses, so every bit becomes a net of its own, spelled per dialect.

## 6. External cells

Step 1 declared transistors, but primitives come in more kinds. A netlist has
to call each kind correctly, and in many SPICE dialects the first letter of an
instance line says what it is. The `element` of an external cell records
exactly that.

| `element` | The name is | CDL line |
| --- | --- | --- |
| `h.MOS` | a transistor model | `M...` |
| `h.RESISTOR`, `h.CAPACITOR`, `h.INDUCTOR` | a passive model | `R...`, `C...`, `L...` |
| `h.DIODE`, `h.BIPOLAR` | a diode or bipolar model | `D...`, `Q...` |
| `h.SUBCKT` | a subcircuit in another file | `X...` |
| `h.BUILTIN` | an element of the simulator itself | (step 11) |

Parameters of an external cell can also be text, such as `flavor="hv"`. A
`str` value is text, and anything else is a number.

```python
rpoly = h.External("rpoly", h.RESISTOR, [h.Port(name="p"), h.Port(name="n")])


class load(h.Subckt):
    a = h.Port()
    b = h.Port()
    r0 = rpoly(l=1e-6, flavor="hv")(p=a, n=b)


print(cdl.write(h.elaborate(load)))
```

```text
* Generated by spicule

.SUBCKT load a b
Rr0 a b rpoly l=1e-6 flavor="hv"
.ENDS load

.END
```

## 7. Shortcuts

Everything so far used the explicit form, which shows exactly what happens but
takes a lot of typing. Spicule comes with a bunch of **shortcuts** (syntactic
sugar) to remove boilerplate and improve readability.

| Explicit | Shortcut |
| --- | --- |
| `h.External("n", element=h.MOS, ports=[h.Port(name="d"), ...])` | `h.External("n", h.MOS, "d g s b")`, a bus as `d[3:0]` |
| `a = h.Port()`, `y = h.Port()` | `a, y = h.Ports(2)`, also `h.Signals` |
| `h.Param(default=2)` | `h.Param(2)` |
| `inv()(a=a, y=y, vdd=vdd, vss=vss)` | `inv()(a, y, vdd, vss)`, in port order |
| `h.Concat(d[3:2], en)` | `(d[3:2], en)` |
| one full call per instance | a partial: `.preset()` connects ports, `.params()` overrides |

Connecting by position can't catch two swapped ports of equal width, so it suits
small cells.

A **partial** holds what several instances share, and works like
`functools.partial`: it fills in part of a call and gives back something to call
later, while the original stays as it is. `.params()` fills in parameters and
can override them, and `.preset()` connects ports for good. A partial needs a
name starting with `_`, which keeps it out of the written netlist, like any
helper.

```python
nch = h.External("nch", h.MOS, "d g s b")
pch = h.External("pch", h.MOS, "d g s b")


class inv(h.Subckt):
    a, y, vdd, vss = h.Ports(4)
    nfin = h.Param(2)
    mp = pch(nfin=2 * nfin)(y, a, vdd, vdd)
    mn = nch(nfin=nfin)(y, a, vss, vss)


class nand2(h.Subckt):
    a, b, y, vdd, vss = h.Ports(5)
    mid = h.Signal()
    _p = pch().preset(d=y, s=vdd, b=vdd)
    _n = nch(nfin=4).preset(b=vss)
    mpa = _p(g=a)
    mpb = _p(g=b)
    mna = _n(d=y, g=a, s=mid)
    mnb = _n.params(nfin=6)(d=mid, g=b, s=vss)


print(spectre.write(h.elaborate(nand2)))
```

```text
// Generated by spicule
simulator lang=spectre

subckt nand2 (a b y vdd vss)
    mpa (y a vdd vdd) pch
    mpb (y b vdd vdd) pch
    mna (y a mid vss) nch nfin=4
    mnb (mid b vss vss) nch nfin=6
ends nand2
```

## 8. Assigning attributes

A class body has to spell out every name, so it can't create names in a loop.
For contents that ordinary Python decides, you can also build a subcircuit by
assigning its attributes. `h.new_subckt` gives an empty one, and a subcircuit
made with a class can be added to in the same way. The rules from step 4 still
apply.

Both a dot and square brackets work, for setting and for reading: `bank.x0` and
`bank["x0"]` are the same attribute.

```python
bank = h.new_subckt("invbank4")
bank.d, bank.q = h.Ports(2, width=4)
bank.vdd, bank.vss = h.Ports(2)
bank.nfin = h.Param(4)
for bit in range(4):
    bank[f"x{bit}"] = inv(nfin=bank.nfin)(bank.d[bit], bank.q[bit], bank.vdd, bank.vss)

print(bank["x0"].name)
print(spectre.write(h.elaborate(bank)))
```

```text
x0
// Generated by spicule
simulator lang=spectre

subckt inv (a y vdd vss)
    parameters nfin=2
    mp (y a vdd vdd) pch nfin=2*nfin
    mn (y a vss vss) nch nfin=nfin
ends inv

subckt invbank4 (d\<3\> d\<2\> d\<1\> d\<0\> q\<3\> q\<2\> q\<1\> q\<0\> vdd vss)
    parameters nfin=4
    x0 (d\<0\> q\<0\> vdd vss) inv nfin=nfin
    x1 (d\<1\> q\<1\> vdd vss) inv nfin=nfin
    x2 (d\<2\> q\<2\> vdd vss) inv nfin=nfin
    x3 (d\<3\> q\<3\> vdd vss) inv nfin=nfin
ends invbank4
```

## 9. Generators

A class describes one cell. Sometimes you need a family of them, such as an
inverter bank for each width. A netlist parameter can't do that, because it only
changes values inside a fixed structure.

A **generator** can. It is a decorated function that builds a cell, and its
arguments are **build parameters**, Python values that decide the structure. It
runs once per distinct value, and the format on the decorator names each cell.

```python
@h.generator("invbank_n{n}")
def invbank(*, n: int) -> type[h.Subckt]:
    class bank(h.Subckt):
        d, q = h.Ports(2, width=n)
        vdd, vss = h.Ports(2)
        nfin = h.Param(4)

    for bit in range(n):
        bank[f"x{bit}"] = inv(nfin=bank.nfin)(bank.d[bit], bank.q[bit], bank.vdd, bank.vss)
    return bank


class top(h.Subckt):
    din, dout = h.Ports(2, width=2)
    vdd, vss = h.Ports(2)
    mid = h.Signal(width=2)
    b0 = invbank(n=2)(nfin=6)(din, mid, vdd, vss)
    b1 = invbank(n=2)()(mid, dout, vdd, vss)


print(spectre.write(h.elaborate(top)))
```

```text
// Generated by spicule
simulator lang=spectre

subckt inv (a y vdd vss)
    parameters nfin=2
    mp (y a vdd vdd) pch nfin=2*nfin
    mn (y a vss vss) nch nfin=nfin
ends inv

subckt invbank_n2 (d\<1\> d\<0\> q\<1\> q\<0\> vdd vss)
    parameters nfin=4
    x0 (d\<0\> q\<0\> vdd vss) inv nfin=nfin
    x1 (d\<1\> q\<1\> vdd vss) inv nfin=nfin
ends invbank_n2

subckt top (din\<1\> din\<0\> dout\<1\> dout\<0\> vdd vss)
    b0 (din\<1\> din\<0\> mid\<1\> mid\<0\> vdd vss) invbank_n2 nfin=6
    b1 (mid\<1\> mid\<0\> dout\<1\> dout\<0\> vdd vss) invbank_n2
ends top
```

The instance `b0` takes three calls, one per layer: build parameters, netlist
parameters, connections. Both instances share one cell, because equal values
give the same cell.

As a rule, a value that changes the structure or is text is a build parameter,
and a number the simulator may vary is a netlist parameter.

## 10. Mistakes

Mistakes are easiest to fix close to where you made them. So spicule raises an
`h.HdlError` as soon as it can tell, naming the Python lines involved.

```python
for mistake in (
    "inv(nfins=4)",
    "inv()(a=1)",
    'inv(nfin="2u")',
    "invbank(n=[2])",
):
    try:
        eval(mistake)
    except h.HdlError as error:
        print(f"{mistake}: {str(error).splitlines()[0]}")
```

```text
inv(nfins=4): inv has no parameter 'nfins' (parameters: nfin)
inv()(a=1): port 'a' of inv can't be connected to 1
inv(nfin="2u"): parameter nfin of inv is a number, got the text '2u'. Subckt parameters are numbers; a text choice is a build parameter of a generator
invbank(n=[2]): generator invbank: argument n=[2] can't be a build parameter, because it isn't hashable; use a tuple instead of a list, for example
```

Some things are suspicious without being wrong, such as a net that floats
(instead of using `h.NoConn()`). `h.elaborate(top, lint=True)` warns about
those, and the netlist stays valid. To trace a netlist line back to its Python
source, pass `origins=True` to a writer, which adds comments such as `// origin:
cells/inv.py:8`.

## 11. A simulation

To simulate a design, you need a testbench around it. A **testbench** is an
ordinary subcircuit that also uses the simulator's own primitives, such as
voltage sources, from `spicule.hdl.builtins`. Ground is just another net here.

```python
from spicule.hdl.builtins import spectre as sp


class tb(h.Subckt):
    supply = h.Param(0.8)
    vdd, a, y, gnd = h.Signals(4)
    dut = inv(nfin=4)(a, y, vdd, gnd)
    vs = sp.vsource(type="dc", dc=supply)(vdd, gnd)
    va = sp.vsource(type="pulse", val0=0, val1=supply, period=1e-9)(a, gnd)
    cl = sp.capacitor(c=1e-15)(y, gnd)
```

A testbench still doesn't say which models to load, what to run or which net is
ground. Those aren't part of the circuit, instead they go in a **simulation**,
a `sim.Simulation`.

Spectre owns the names of analyses and of their parameters, so you can give any
of them. `params` sets parameters that the top cell declares, and a sweep or a
Monte Carlo run holds the analyses it repeats in `children`.

```python
from spicule import sim

run = sim.Simulation(
    h.elaborate(tb),
    top="tb",
    ground="gnd",
    params={"supply": 0.7},
    includes=[sim.Include("models.scs", section="tt")],
    options=sim.Options("opts", temp=27),
    saves=["y", "dut.mp:d"],
    analyses=[
        sim.Analysis("op", "dc"),
        sim.Analysis("tr", "tran", stop=2e-9),
        sim.Analysis("sw", "sweep", param="supply", values=[0.6, 0.8], children=[sim.Analysis("op", "dc")]),
    ],
)
print(spectre.write(run))
```

```text
// Generated by spicule
simulator lang=spectre

parameters supply=700e-3
include "models.scs" section=tt

subckt inv (a y vdd vss)
    parameters nfin=2
    mp (y a vdd vdd) pch nfin=2*nfin
    mn (y a vss vss) nch nfin=nfin
ends inv

// top: tb
dut (a y vdd 0) inv nfin=4
vs (vdd 0) vsource type=dc dc=supply
va (a 0) vsource type=pulse val0=0 val1=supply period=1e-9
cl (y 0) capacitor c=1e-15

opts options temp=27
save y dut.mp:d

op dc
tr tran stop=2e-9
sw sweep param=supply values=[600e-3 800e-3] {
    op dc
}
```

`spectre.write` takes the netlist or the simulation. A netlist becomes a library
of subcircuits, and a simulation becomes a deck to run. For anything the
structure doesn't cover, `raw=[...]` and `sim.Raw` hold Spectre text as it is.

## 12. Files and the IR

A netlist or a simulation can also be kept as a file. `jsonio` writes either as
JSON, for looking at it, comparing runs with `diff`, or keeping a design without
its Python.

```python
from spicule.dialects import jsonio

text = jsonio.write(run)
print(text.splitlines()[1])
print(jsonio.read(text) == run)
```

```text
"format": "spicule.sim/1",
True
```

The netlist from `h.elaborate` is plain data: frozen dataclasses with one
validator, and nothing of the HDL left. A tool can read this IR directly.

```python
import spicule.ir as ir

netlist = h.elaborate(inv)
for cell in netlist.cells:
    print(type(cell).__name__, cell.name, [port.name for port in cell.ports])
mp = netlist.cells[-1].instances[0]
print(mp.name, mp.cell, ir.format_expression(mp.params[0].value))
```

```text
External pch ['d', 'g', 's', 'b']
External nch ['d', 'g', 's', 'b']
Subckt inv ['a', 'y', 'vdd', 'vss']
mp pch 2*nfin
```
